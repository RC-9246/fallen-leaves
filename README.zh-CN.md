# Fallen Leaves · 落叶

落叶是一款轻量、离线的 Android 运存工具。打开「运存」就能看到系统可用内存、文件页缓存、可回收内核对象和交换区用量。内核支持时还会显示内存压力。简体中文界面使用原生 Java 编写，运存、存储、记录、图表和弹窗默认采用系统配色。

[下载已签名 APK](https://github.com/RC-9246/fallen-leaves/releases/latest) · [English](README.md)

## 怎么用

支持 Android 8.0 及以上。查看运存和打开应用的系统详情页都无需 Root。要使用内核回收、向缓存进程发出回收请求或清理旧诊断文件，可通过 KernelSU 等兼容的 Root 管理器授权。

点任一页面顶端的「设置」打开「界面与提示」。主题可以选「跟随系统」「浅色」或「深色」，点「保存」生效。关闭「显示清理完成弹窗」后，仍可在「记录」查看手动运存回收、后台进程回收请求和诊断清理的结果。失败或只完成一部分时仍会提示。

| 入口 | 功能 | 权限 |
| --- | --- | --- |
| 运存概览 | 物理内存、交换空间和系统缓存三组可独立折叠，会记住展开状态。前两组显示已用、可用、总量和使用率，达到 70%、90% 时分级变色。缓存组显示文件页估算、可回收内核对象、两者占物理内存的比例，以及可读取的内存压力。蓝色深浅表示缓存占比。 | 无需 Root |
| 可用运存趋势 | 运存页可见时每秒采样，显示最近两分钟的曲线和文字摘要。长时间停止采样会在曲线上留出空档。 | 无需 Root |
| 应用占用排行 | 在「存储 → 应用占用排行」授予系统的「使用情况访问权限」，即可按缓存或总占用给符合条件的用户应用排序。点选应用可进入系统设置。总占用已包含缓存，系统未提供的数字会标为不可用。 | 无需 Root，需单独授权统计 |
| 运存 | 勾选文件页和可回收内核对象并保存后，主按钮按组合执行。「单项」菜单只执行一次，不修改组合。在文件页确认框勾选「下次不再询问」并点「回收」，即可跳过今后的文件页确认。可在运存页重新开启「手动回收前确认」。此偏好也适用于快捷磁贴，包含内核对象的操作始终弹出停顿提示。结果显示操作前后读数。 | 需要 Root |
| 快捷设置 | 在系统快捷设置的编辑页添加「回收文件页」磁贴，点击即可手动回收文件页。 | 需要 Root |
| 后台应用 | 选择已进入缓存状态的用户应用进程。发送请求前会重新核对身份和缓存状态。释放多少由目标应用决定，Android 14 及以上可能忽略请求。 | 需要 Root |
| 自动监控 | 独立开关：已用运存达到 1–99%（预设 90%），或每 1–1440 分钟（预设 30 分钟）。两者默认关闭，可选仅提醒或用 Root 自动回收干净文件页。两个条件在同一次检查同时满足时只执行一次。常驻通知提供「调整」和「停止」。 | 仅提醒无需 Root，回收需要 Root |
| 应用缓存 | 打开所选应用的系统详情，在「存储」中手动点「清除缓存」。「清除存储空间／清除数据」会清空该应用的数据。 | 无需 Root |
| 旧诊断文件 | 预览符合规则的文件和实际磁盘占用。文件默认未勾选，手动选择并确认后才会永久删除。 | 需要 Root |

占用阈值每 30 秒采样，连续三次达到阈值才触发。同类阈值操作至少相隔 30 分钟，通常需回落三个百分点才重新准备触发。设为 1–3% 时，降到该阈值以下即可重新准备。定时条件独立计时。休眠可能推迟执行，错过多个周期在恢复后合并为一次。修改运行中的条件会重新计时。开启监控需要允许通知，重启后需手动开启。

## 扩展回收范围

在「运存 → 扩展回收范围」中，每项都有独立保存的开关。五项新增操作默认关闭，打开开关后还要单独执行。涉及应用时每次选择一个当前缓存的用户应用。原有的全机干净文件页、可回收内核对象、通知进程自行回收、删除旧诊断也可以独立关闭，升级后默认沿用原有行为。快捷磁贴和自动监控只会回收已获允许的全机文件页。

| 范围 | 操作和结果 |
| --- | --- |
| 指定应用的匿名页 | 通过该应用各缓存进程的 `/proc/PID/reclaim` 请求内核回收可换出的匿名页，包括符合条件的 Java 堆和原生堆页。需要可写的逐进程接口，且至少启用一个交换设备。所有启用的交换设备都必须是 zRAM。进程可以保留，返回时可能需要解压。 |
| 指定应用的文件映射 | 只对目标缓存应用发出文件页回收请求。代码、共享库和资源可能需要重读。其他进程仍在使用的共享页可能继续驻留。部分厂商驱动按映射类型选择区域，其中的私有写时复制页也可能被换出。 |
| 接受下次冷启动 | 独立开启并确认后，请 Android 通过 `am kill --user` 结束所选应用符合条件的缓存进程。报告已退出的原进程数和操作后进程数。应用可以再次启动；未持久化的内存状态可能丢失。 |
| 整理 zRAM 压缩池 | 在已初始化的 zRAM 设备内整理压缩对象，让分配器有机会归还整页。分别显示物理占用变化和内核计数的整理页数。零收益会显示零。 |
| 可丢弃 ashmem | 用落叶自己的临时区域检验旧驱动能否真正标记可丢弃，再按需请求系统回收此类区域。范围限于应用主动允许丢弃的共享内存。仅保留兼容节点或使用 memfd 的设备会显示不可用。 |

目标应用的两组数字分别为同一批存活进程的**驻留内存 RSS 合计**，以及整机 **zRAM 物理占用**（`mm_stat` 的 `mem_used_total`）。例如，RSS 减少 300 MiB、zRAM 增加 110 MiB，粗略净收益为 190 MiB。其他进程的同期活动和共享页重复计数都会影响估算；进程更替、计数缺失或操作只完成一部分时，结果会标出限制。内核受理请求后，实际回收量也可能为零。[Android 11 缓存进程优化器](https://android.googlesource.com/platform/frameworks/base/+/android-11.0.0_r1/services/core/java/com/android/server/am/CachedAppOptimizer.java) · [zRAM 计数说明](https://docs.kernel.org/admin-guide/blockdev/zram.html) · [旧版 ashmem 实现](https://android.googlesource.com/kernel/common/+/e515b9902f5fa362ca66db9b01e7b2161c324c06/drivers/staging/android/ashmem.c)

## 清理边界

**运存。** 只有单独确认「允许应用下次冷启动」才会请求 Android 结束所选应用的缓存进程。后台进程列表排除系统应用、落叶自身、可识别的 VPN 服务应用和共享应用身份的进程。详情中的 RSS 包含共享内存页。界面上的可用运存是全系统读数，前后差值也会受到其他应用影响。频繁丢弃缓存可能使下次启动变慢。交换区用量是逻辑空间，不能用来推算 zram 实际占了多少物理内存。

**存储。** 直接删除仅限指定命名规则的 Android 原生崩溃记录、ANR 追踪、厂商 WLAN 故障转储，以及一加编号诊断目录中的四类历史日志。候选文件须是修改时间已满七天、只有一个硬链接的普通文件。删除前再核对规范路径、类型、年龄和扫描时的文件信息，跳过检查未通过的项目。删掉的日志无法再用于排查那次故障。完整的文件名规则见 [Diagnostics.java](app/src/main/java/dev/pagetrim/app/Diagnostics.java)。

下载目录、保留的 APK、照片、聊天记录和其他应用的私有数据都不属于诊断清理范围。应用缓存只通过系统设置手动清理。落叶需要读取应用列表来显示可选项目，无联网权限、广告或第三方运行库。最近 30 次操作记录保存在本机。

## 构建和验证

准备 JDK 17、Android SDK Platform 34、Build Tools 34.0.0、Android NDK r27c（27.2.12479018）、Bash、zip 和 OpenSSL。测试还需 Python 3 和本机 C 编译器。请将环境变量 `ANDROID_HOME` 指向 SDK；若 NDK 单独安装，可通过 `ANDROID_NDK_HOME` 指定目录。在项目根目录运行以下命令。

```sh
./tests/test-policy.sh
python3 tests/test-target.py
./tests/test-pools.sh
./build.sh
```

发布包会生成在 `build/Fallen-Leaves.apk`。调试构建使用 `./build.sh debug`。签名文件保存在源码目录外，通过 `FALLEN_LEAVES_SIGNING_DIR` 可在多次构建时复用自己的签名。公开发行版沿用清页 PageTrim 的包名 `dev.pagetrim.app` 和签名，可以覆盖升级。自行构建的版本需要使用相同密钥才能覆盖已安装的版本。最低 API 26，目标 API 33。

本地测试覆盖目录及文件名限制、文件年龄、硬链接、磁盘占用、空选择和无效回收模式。在 Android 11 模拟器上实测了 1.0.1 覆盖升级、前台运存趋势、仅提醒监控的启停、从授权页返回、两种排序及跳转应用设置。两个测试应用分别写入了不同大小的缓存和普通数据，以验证排序。阈值、冷却时间和模式隔离另使用模拟读数验证。底层功能已在 Android 11 AOSP 模拟器验证，包括三种内核回收模式和选中诊断文件的删除。

1.3.0 的回归测试覆盖进程身份变更、缓存应用回到前台、内核接口缺失、RSS 与 zRAM 读数、零收益、计数重置和部分完成。Android 11 AOSP 模拟器从 1.2.1 覆盖升级后，已核验九项开关的默认值、重启后的保存、组合操作的开关限制和系统深浅色；普通应用身份缺少 Root 时，界面会提示授权问题。用特权测试入口验证了缓存进程退出、zRAM 整理和旧版 ashmem 回收。在内核为 4.19.160 的一加 8T 上，两种逐进程回收都使用临时测试进程，回收后进程仍能读回数据。这台手机的 ashmem 驱动在取消固定后仍报告页面已固定。真机验证使用 Root shell，未在手机上安装新版落叶。
